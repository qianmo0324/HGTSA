# HGTSA 柔性作业车间调度复现

本项目使用 Python 实现混合遗传禁忌搜索算法 HGTSA，求解以最小化最大完工时间（Makespan）为目标的柔性作业车间调度问题。

复现依据为所提供论文及《详细复现步骤_格式整理版.docx》。实验范围限定为 **Brandimarte MK01–MK10**，直接使用项目内已有数据，不涉及 BCdata、DPdata 或 06a 参数调优。

## 3. 运行模式与参数

`--profile` 表示选择一套预设参数。命令行单独指定的参数会覆盖相应默认值。

| 参数 | `paper` 正式参数模式 | `smoke` 快速检查模式 |
|---|---:|---:|
| 种群规模 PS | 30 | 4 |
| 交叉概率 Pc | 0.9 | 0.9 |
| 变异概率 Pm | 0.1 | 0.1 |
| smallIter | 1200 | 5 |
| largeIter | 15000 | 12 |
| 最大 GA 代数 | 100 | 2 |
| 每例独立运行次数 | 10 | 1 |
| 每次运行时间上限 | 不限制 | 3 秒 |

前五项正式参数取自论文。**论文没有明确给出最大 GA 代数的具体值，本项目默认取 100**，可通过 `--max-generations` 修改。

### smallIter 与 largeIter

- `smallIter`：交叉、变异后的候选解执行小规模 TS 时，允许连续不改进的最大步数。
- `largeIter`：新种群个体执行大规模 TS 时，允许连续不改进的最大步数。

它们不是固定的总迭代次数。只要该次 TS 找到更好的局部最优值，连续未改进计数就会清零，因此实际总步数可能更大。

找到 LB、达到最大 GA 代数或触及显式设置的时间上限时，当前次求解会停止。时间上限在计算步骤之间检查，可能有少量超时。

### 当前两批结果的区别

- `results/paper`：目前完成四例，各 10 次，采用正式参数且不限制时间。
- `results/smoke`：十例各一次，采用小种群和较小 TS 参数；当前保存批次通过命令行将每次上限设为 **60 秒**，已经替换此前的 15 秒结果。

**代码中 smoke 的默认上限仍为 3 秒，60 秒只是当前批次通过 `--time-limit 60` 覆盖后的设置。** 每批实验的实际参数以其 `manifest.json` 为准。

## 4. 运行与中断续跑

### 继续现有正式实验

现有实验最初选择了 MK01–MK10，各运行 10 次。若要继续完成后续算例，保持原参数和输出目录，执行：

```powershell
python run_experiments.py --profile paper --runs 10 --output results/paper --resume
```

在代码、参数和数据指纹均与原实验一致时，程序会跳过已经保存的 40 次运行，处理尚未完成的部分。它会先校验配置和已保存记录；如校验不通过，会报错而不会混用结果。

**当前续跑状态：** 本次整理时发现，当前代码指纹与 `results/paper/manifest.json` 中记录的指纹不一致，因此上述命令目前会拒绝续跑。需要恢复原实验使用的代码版本，或使用当前代码另建输出目录开始一批新实验。原有 40 份结果仍可用于统计和绘图；不要修改原 manifest 的指纹来强行混合结果。

### 另起一批完整实验

使用一个尚不存在或为空的输出目录：

```powershell
python run_experiments.py --profile paper --runs 10 --output results/paper_new
```

### 单算例限时测试

例如，使用论文参数测试 MK01 一次，并限制在约 60 秒内：

```powershell
python run_experiments.py --profile paper --instances MK01 --runs 1 --time-limit 60 --output results/local_test
```

这属于限时实验，不保证执行完 TS 搜索预算。不希望限制时间时，去掉 `--time-limit 60`。

### 按当前 smoke 设置另跑一批流程测试

如需使用相同参数设置重跑十个算例各一次，可指定一个新的空目录，避免覆盖已保存的结果：

```powershell
python run_experiments.py --profile smoke --runs 1 --time-limit 60 --seed 20261019 --output results/smoke_new
```

此命令使用执行时的代码版本。当前 `results/smoke` 是已保存的实验批次；后续代码变化和机器负载会影响限时结果，即使种子相同，也不保证与本节表格逐项一致。通用运行入口默认会生成基础图表，而当前 smoke 展示已按要求删除图表，只保留表格和说明。

### 中断和关闭 VS Code 后如何继续

先在终端按 `Ctrl+C`，等待程序退出后再关闭 VS Code。重新打开后进入相同项目目录，在原命令后添加 `--resume`。

**续跑的单位是一次完整的独立运行，不是某一步迭代。** 例如 MK01 已完成 10 次、MK02 已完成 3 次，续跑将从 MK02 第 4 次开始；中断时尚未保存的那一次会重新计算。

续跑需保留原输出目录、参数、随机种子、数据和求解相关代码。程序会核对配置及数据、代码的 SHA256 指纹。更改参数时请使用新输出目录，不要手动修改 `manifest.json` 跳过校验。

同一随机种子和相同迭代预算可复现搜索过程；限时运行还会受系统负载影响。完整实验期间应保持电脑接通电源并避免睡眠。

### smoke 展示表为什么不单列总体 MRE

**单次测试也可以计算 MRE；没有把它放入展示表，不是因为公式不适用，而是为了避免将这批流程测试误读为论文条件下的完整性能评价。** 按当前十例实际结果计算，b-MRE 与 av-MRE 均为 **36.42%**；底层 `summary.json` 保留的未四舍五入值约为 36.4183028773%。这表示：在本批简化参数和单次最多 60 秒的设置下，十个算例的实测 Makespan 相对各自 LB 的百分比差距，等权平均约为 36.42%。它不是算法计算耗时，也不是达到最优的成功率。

若在表尾同时展示 `b-MRE=36.42%` 和 `av-MRE=36.42%`，两项数值在本批中不会提供两份独立的质量证据。由于每例只有一次观测，该例的 Best 与 Mav 必然相同，进而两种 MRE 也必然相同。**它们相等只是样本数量造成的算术结果，不表示算法稳定，不能说明更换随机种子后的波动，也不能估计十次独立运行的平均表现或其中的最好值。** 十个不同算例各一次，不能替代同一算例的十次重复实验。

MRE 在这里仍有用途：它能用一个百分数概括这批限时观测与下界的总体差距，也可以用于实验条件、数据范围和运行次数一致的探索性对照。但把它直接与论文的 b-MRE≈0.21%、av-MRE≈0.29% 并列，容易把计算预算、种群规模、TS 深度和重复次数的差异误解为算法本身的性能差异。它也不能与当前 paper 四例子集的 0% 直接比较，因为算例覆盖范围不同。**目前缺少的是对完整性能和随机稳定性的推断依据，而不是描述这批观测值的数学意义。**

此外，总体平均会隐藏算例间的差异。例如，本批 MK01 的 RE 为 0%，而 MK10 约为 117.99%；只写总体 36.42% 看不出哪些算例已达到下界、哪些仍有较大差距。因此，流程测试的展示表优先保留逐算例结果和 LB；如汇报时补充总体 MRE，应同时注明“smoke 简化参数、每例一次、单次最多 60 秒、十例等权平均”，并保留逐例数据。省略 MRE 只是展示侧重点的选择，不会消除结果差距，也不能代替这些条件说明。

## 6. 指标定义与 MRE 为 0 的原因

| 指标 | 含义 |
|---|---|
| LB | 所提供论文表 5 采用的下界 |
| UB（原论文） | 所提供论文表 5 列出的已知上界 |
| UB（本机） | 本批已完成运行得到的最好可行解值，等于 Best |
| Best | 某算例各次独立运行中的最小 Makespan |
| Mav | 某算例各次独立运行的 Makespan 算术平均值 |
| b-MRE | 各算例 Best 相对 LB 的误差的算术平均 |
| av-MRE | 各算例 Mav 相对 LB 的误差的算术平均 |

误差均以百分数表示，计算如下：

```text
Best RE = 100 × (Best − LB) / LB
Mean RE = 100 × (Mav − LB) / LB
b-MRE   = 统计范围内各算例 Best RE 的算术平均
av-MRE  = 统计范围内各算例 Mean RE 的算术平均
```

各算例权重相同。`known_ub_re_percent` 单独记录论文 UB 的误差，不替代本次实测的 Best RE 或 Mean RE。

当前 MK01–MK04 的每一次运行都达到 LB，因此各例均有 `Best = Mav = LB`，两种 RE 全为 0，四例平均后仍为 0。**这不是把论文指标写成 0，也不是四舍五入造成的。**

论文十例结果中，MK01–MK09 的误差为 0；MK10 的 LB 为 189、Best 为 193、Mav 为 194.5。因此论文总体指标约为：

```text
b-MRE  = [100 × (193 − 189) / 189] / 10   ≈ 0.21%
av-MRE = [100 × (194.5 − 189) / 189] / 10 ≈ 0.29%
```

统计表仅在 Overall 行列出这两项跨算例指标。部分实验的统计范围以 `summary.json` 中的 `scope` 和每例 `runs` 为准。`complete_br10` 只表示十例各完成十次，不表示已经达到论文指标。

报告当前结果时，可表述为：**“在 MK01–MK04 四个算例上各独立运行 10 次，所有运行均达到对应下界，该子集的 b-MRE 和 av-MRE 均为 0%。”**

## 8. 算法实现与复现边界

每代主流程为：轮盘赌选择 → 路径重连交叉 → 变异 → 候选解小规模 TS → 选择子代 → 子代大规模 TS → 父子种群合并择优。

工艺弧保证工件加工顺序，机器弧保证独占加工；每道工序只分配到一台可选机器且不可中断。解码通过拓扑排序和最长路计算工序时间，有环序列视为不可行。输出前检查工艺顺序、加工时间、机器重叠及 Makespan。

复现报告需要说明以下选择和差异：

1. **编码**：内部使用唯一工序 ID，消除一个工件在同一机器上加工多道工序的歧义。JSON 中 `machine_sequences` 使用从 0 开始的工序 ID，`operations` 提供映射，`job_sequences_1based` 提供工件编号视图。
2. **修复方法**：采用保持机器分配的优先级拓扑修复。引用的 Ren & Wang（2012）正文未能访问核实，不能称为已核实的原方法逐步复现。
3. **N8 邻域**：参考作者的 [N8 预印本](https://arxiv.org/abs/2109.02843) 第 3.2 节，实现块内边界插入及关键工序的块外移动；使用命题条件与完整 DAG 检查。未使用全部非改进剪枝或快速近似评价，邻居数量和速度可能不同。
4. **k-insertion**：删除被移动工序的机器弧、保留工艺弧后，按祖先与后继确定可行插入区间。该方式保证无环，但不逐式复刻主论文四组时间集合公式。
5. **路径重连**：先匹配机器再交换位置，原始路径保留到取样后才修复。采用 `alpha=max(1,ceil(sd/5))`、`beta=max(2,ceil(sd/10))`；无内部取样点时保留起始亲本。论文未明确这些整数舍入和退化情况。
6. **初始化**：随机选择就绪工序和可选机器，插入最早可用空闲间隙；并列最优邻居使用随机种子打破平局。
7. **禁忌属性**：期限取 `ceil(15+n/m)`，记录逆向插入位置；相邻交换采用统一的工序对顺序属性，避免同一逆向交换换一种描述后绕过禁忌。严格改善已知最好解时允许特赦。
8. **实验设置**：直接采用论文最终参数，不运行 06a DOE。最大 GA 代数默认 100 是本项目的选择，具体批次参数以 `manifest.json` 为准。

当前代码还包含单次移动的轻量精确 Makespan 评价，并在需要时才构建完整 Schedule。它减少候选评价中的对象构建，但不属于已保存四算例实验批次所记录的代码版本。本 README 中的运行时间仅对应原实验记录，不能用来衡量修改后的版本。
